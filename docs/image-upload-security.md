# 11.2D.7 — Image upload validation

Install on the standalone package only. Preview the guarded installer first. No Composer or npm dependency changes. Existing image records are not rescanned.

The built-in upload request validates real local PHP upload bytes before storage. Fileinfo MIME must agree with getimagesizefromstring type, and the format must be one of JPEG, PNG, WebP or GIF allowed by the host. SVG is never accepted. UUID filenames use jpg/png/webp/gif from verified MIME, not client input. Invalid input produces normal Laravel 422 validation errors. Invalid host configuration throws a LogicException. The upload response is unchanged.

Defaults: 5120 KiB, 8192 width, 8192 height, 40,000,000 canvas pixels. Positive integer configuration limits cannot exceed 20480 KiB, 16384 for each dimension or 100,000,000 pixels. Set max_width, max_height, max_pixels under image_upload. Old configs lacking these keys use defaults. Allowed MIME list may narrow supported types, not expand them. Unknown or empty lists fail closed. A configured max_size above 20 MiB requires revision. The actual byte read is bounded to configured max plus one byte. PHP request/body limits still apply.

Container checks: PNG chunk boundaries, CRCs, initial IHDR, IDAT and terminal IEND; JPEG marker bounds before first scan and terminal EOI; GIF block and frame rectangle boundaries and terminal trailer; WebP RIFF/chunk sizes and image data marker. These are deliberately NOT a full decompression, decoding, malware scan or re-encoding step. Malformed compressed content, malicious metadata, some polyglots and animation resource abuse can still exist. Canvas pixel limits do not bound total decoded frames; metadata is retained. JPEG extension now canonical jpg. Strict structural checks can reject files tolerated by permissive browsers. Serve uploaded files only with non-executable static configuration and correct content type/nosniff. Consider sandboxed decoding/re-encoding, quotas and scanning according to the host threat model. Do not trust user-provided filenames or pass request text as a local path.

Custom host endpoints are not automatically protected. During 11.2H, after standard upload authentication/authorization and file validity checks, call `ImageUploadInspector::inspectFile($file->getPathname(), config('tiptap-editor.image_upload', []))`, convert InvalidUploadedImage to Laravel validation errors, use returned extension, and retain owner directory and storage lock. Any stricter host limits remain authoritative. Finalization of existing temporary media does not revalidate bytes in this step.

The old PNG fixture had an invalid IDAT CRC; prior tests are updated with a valid 1x1 PNG. New tests use actual generated raster fixtures, no GD required. Run the targeted ImageUploadInspectorTest and ImageUploadContentTest, full composer test:13 and test:12, composer audit, platform checks and strict optimized autoload. Browser rendering and real host integration remain separate acceptance gates.
