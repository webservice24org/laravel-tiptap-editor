# 11.2D.6 - Editor HTML sanitization policy

Candidate package; do not publish or integrate into host applications until both Laravel suites, the lower PHP matrix, browser and host regression gates are complete.

## Public API

`EditorHtmlSanitizer::sanitize(?string $html): string` is unchanged. Null and whitespace-only input returns an empty string. Input must be valid UTF-8, contain no NUL bytes and be at most 2 MiB; a 20,000 visited-node / 100-level rendering budget rejects overly complex trees with `InvalidArgumentException`. Limits apply to the supplied fragment, not entire application documents. They are not a complete denial-of-service guarantee (parsing precedes tree traversal). Keep request/body limits at the host boundary.

PHP 8.4+ uses `Dom\HTMLDocument` with its HTML5 parser and namespaces. PHP 8.2/8.3 uses legacy `DOMDocument` only to extract nodes. Neither parser is trusted as a sanitizer: new markup is generated from an exact tag and attribute allowlist, escaping text and every accepted attribute value. Unknown ordinary wrapper elements are unwrapped; active content, raw-text, foreign, template, form and embedded object subtrees are discarded. Comments, IDs, names, event attributes, `srcdoc`, arbitrary data attributes and arbitrary classes are not emitted. Legacy parsing can lose or rearrange malformed markup, and the two parsers may normalize HTML differently. Do not interpret this as a complete security proof. The output is for a normal HTML body fragment only, never a script, style, attribute, XML, SVG, MathML or other execution context.

## Value policies and compatibility changes

- Links: HTTP(S) absolute URLs without userinfo, single-slash root-relative paths, or `#` fragments. Images: HTTP(S) absolute or single-slash root-relative paths. Protocol-relative URLs, backslashes, controls, whitespace and non-HTTP schemes are not allowed; absolute URLs must pass PHP URL validation (use punycode domains and encoded spaces). Empty or unsafe `href` is removed; an image with no safe `src` is removed. Blank-target links receive noopener/noreferrer; supported SEO rel tokens are retained.
- Video: HTTPS only, exact YouTube/youtube-nocookie hosts with `/embed/{11-character-id}` or `player.vimeo.com/video/{numeric-id}`. No explicit port or fragment. Query strings are retained when URL validation passes, including Vimeo private-video parameters; the provider is trusted for playback and this does not guarantee absence of third-party redirects or tracking. Iframes are regenerated with a fixed permission list, lazy loading, fullscreen and referrer policy. No user-supplied permissions, fallback markup or srcdoc. Autoplay, clipboard-write, accelerometer, gyroscope and web-share permissions are no longer explicitly granted. Actual playback/fullscreen compatibility needs browser QA.
- CSS: restricted property names and value grammars; known formatting, color, bounded size/margin/padding and table/media custom properties only. No arbitrary functions, CSS escapes, URLs, `var()`, `calc()`, `!important`, comments or arbitrary properties. Some otherwise legitimate custom CSS and classes will be removed. Supported rendered editor classes are explicitly listed; arbitrary application classes must not be trusted from rich content. Colors accept a limited token grammar (invalid-but-inert names may still be ignored by browsers).
- News Blocks: article `data-url` and `data-thumbnail` are validated independently of the rendered link/image. Title, excerpt, category and ID are escaped plain attribute text, not trusted identifiers or HTML. Known metadata markers and block styles are retained. Host JavaScript must still handle these values as text and validate URLs at their own sinks, never use them as executable code or raw HTML.
- Media: canonical `data-mw-path` on figure/image and supported markers/width/alignment/caption are retained. Invalid path attributes are removed, not normalized. Ownership and disk checks remain in the finalizer, not in this sanitizer. Existing public image URLs remain public. Sanitization cannot establish document/tenant access, image content validity or file ownership.
- Tables: existing width modes, alignments, border color/style/width, padding, row/column spans and column widths retained within the policy limits.

## Integration requirements

Host applications must sanitize server-side before persisting editor HTML and re-sanitize finalized HTML before storage/rendering, because media finalization is a separate parser/rewriter and host-generated values may be added after the first sanitization. Avoid applying untrusted mutations afterward. Browser DOMPurify remains useful but is not the server authority. Existing stored HTML is not migrated by this patch; audit existing content on read or via a controlled migration after backups and compatibility review. Review CSP and safe rendering contexts separately. Custom upload controllers still need the owner and lock helper integration from earlier phases.

## QA

Run the targeted policy, sanitizer and sanitized-media integration suite plus complete `composer test:12` / `composer test:13`, Composer audit, platform and strict autoload checks. This package has 36 additional test cases (22 policy, 12 sanitizer, 2 integration), expected total 161. Lower PHP versions, native/legacy DOM parsing, malformed HTML/mutation XSS corpus and browser playback/reparse testing are not yet certified. No frontend or Composer version changes are included.
