# 11.2D.3 - Structured managed media finalization

Standalone development package only. Requires the green D.2 baseline. No migration, frontend rebuild, Composer dependency changes or host deployment.

## Contract

Sanitize editor HTML in the host application before calling `EditorMediaService::finalize($html, $trustedDestination, $trustedGuard)`. The existing signature and `extractManagedPaths()` public API are preserved. A real `data-mw-path` attribute is read using DOMDocument rather than regular expressions. Canonical paths are deduplicated in document order. Comments, ordinary text, and attributes with similar names do not create storage references. Noncanonical paths are ignored as in D.1; no storage operations occur for them. Content without recognized temporary references is returned unchanged.

Temporary media must belong to the current server-derived owner (D.2) and must be a figure with `data-mw-image` containing exactly one direct img, or a standalone img carrying the managed path. Nested managed references and unsupported elements are rejected. The associated img src must exactly match the URL generated by the configured disk (for the public disk, `/storage/<path>`). Custom host controllers must use the same convention. Existing permanent references are not moved. Multiple references to one owned upload move the file once and rewrite each associated image. Unmanaged images, links and text are not rewritten, even if their URL happens to match a moved file; hosts must use managed references for images they expect to finalize. Content containing moved temporary media is serialized as HTML; quotes, case, entity representation and formatting can be normalized, not byte-for-byte identical. UTF-8 input is required. The public API still accepts trusted host custom permanent destinations.

All owner checks and reference shape checks precede opening storage. All source URL matches, source regular-file existence checks (adapter `fileExists`), planned destinations and URL resolutions precede storage moves. A Laravel FilesystemAdapter (including its local/cloud subclasses) is now required for finalization, not a custom implementation of only the generic filesystem contract. Missing source, mismatched source URL, destination collision or unavailable URL throws; the caller must not save the original HTML as a fallback. A false or thrown move also stops the request; it does NOT provide an automatic rollback for already completed moves. Collision checks are preflight only, not atomic across concurrent writers. D.4 will address compensation and failure boundaries; D.5 will address cleanup coordination. Public storage reads remain public. This is not image validation or a tenant/document ownership policy.

## Parser limitation

DOMDocument uses the libxml HTML parser, not a browser-equivalent HTML5 parser. This is a structured attribute rewrite of already sanitized editor content, not HTML sanitization or XSS protection. Malformed HTML may normalize differently; the wrapper checks reject some escaped fragments, not all malformed inputs. Do not use this class as a sanitizer. The authoritative sanitizer and parser-differential/security tests are separate D.6 work. Symlink/junction and concurrent filesystem risks remain outstanding. Do not publish or deploy this intermediate package.
