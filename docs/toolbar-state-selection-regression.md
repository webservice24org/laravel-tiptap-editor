# 11.2F.3G — Toolbar state and selection synchronization

Baseline: e3d0307 (F3F Fix 1 accepted by user; three workflows green). Scope: reactive contextual table state and guarded actions, selection protection and cross-instance regression. No dependencies, schema, CSS, PHP or workflows changed.

The main toolbar already subscribes to inline, block, list, alignment, link, typography and history state. TableContextualToolbar previously subscribed only to cell attributes, while eight structural buttons read `editor.can()` in render and four had no availability guard. Equal-style cells can have different merge/split availability. Now all twelve structural commands subscribe to and recheck their native capability. Cell alignment buttons expose explicit aria-pressed and preserve selection; cell controls require an editable table context. Color inputs retain native interaction. Main inline/block action handlers and clear formatting recheck capability; insertion buttons preserve mouse selection. No changes to multi-cell attribute semantics, table visibility detection, color normalization, modal focus management, source mode behavior or media callbacks: those remain in F4–F7. No global keyboard listener or custom selection dispatch.

Five additional browser groups run after all existing 80 groups: table entry/exit, cell attribute state, split availability on equal-style cells, cell alignment with undo, and independent editor state/history. Use actual installed package, native DOM selection, actual toolbar clicks, exact live and saved HTML checks for selection-only operations. The second editor is mounted only for the last test, and has isolated value/change state. No editor internal API injection. Actual runtime acceptance requires local React 18 and 19 runs plus all three hosted workflows. Existing test fixture helpers are reused; all prior check groups remain required.

The static contract inventory records new helper expressions, command wiring, capability subscriptions and ARIA state. Native table capabilities are exercised by instrumented doubles in unit tests, not by a real ProseMirror runtime. Table structural behavior including multi-cell merge/split operations, headers, mixed selection attributes, media/dialog lifecycle, full accessibility and source-mode security remain in their respective later phases. No new public APIs. Fresh production build required.
