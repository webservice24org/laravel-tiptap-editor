# 11.2F.3D — List nesting and alignment regression

Baseline: the accepted F3C Fix 3 payload and all 59 prior baseline hashes, plus original EditorIcons.tsx verified against the original source upload. The user reported all F3C acceptance gates passed; the final commit SHA and fresh CI artifacts were not provided.

- Bullet/ordered list toggles, list indent/outdent and four alignment buttons use transaction-driven state and command availability. Mouse-down prevents selection loss, with command rechecks before focus/dispatch.
- Indent sinks a list item under a previous sibling; Outdent lifts it one level (and can exit a top-level list). No freeform paragraph indentation, margin changes, task lists, numbering-type controls, or new keyboard handlers are introduced. Native list Tab/Shift+Tab behavior is regression tested. Nested list activity continues to follow Tiptap's isActive semantics; an unstyled paragraph has no explicit alignment pressed state.
- Paragraph/heading alignment is supported, including compatible multi-block selections. Mixed selections with unsupported text blocks or block atoms are rejected; existing table-specific alignment remains separate. No extension/schema changes.
- Both sanitizers preserve canonical positive decimal `ol[start]` values from 1 to 99999 only; zero, negative, leading zero, malformed and out-of-range values, and start on other elements, are rejected. This deliberately bounded policy is not full HTML ordered-list semantics. No type/reversed/value attributes added. Existing backend style rules remain unchanged.
- Browser checks reuse the corrected F3C native range helper and start selection-only fixtures with a trailing paragraph. The structural assertion compares both live and saved DOM hierarchy, exact text, inline marks, explicit alignment and start. Only one optional empty trailing paragraph is allowed when requested. Both React versions must pass all existing groups plus the 14 new named groups. Tests use actual UI buttons and native keyboard interactions; no private editor transaction injection.
- Three PHP regression tests verify list structure, restricted ordered starts and alignment sanitization. No dependency or CI workflow changes. The existing runner requires the `lists` browser section. Full browser and PHP suites must pass locally and in CI before acceptance.
