# F.6 Visual / Code mode security regression

Scope: existing Visual/Code functionality only. Raw Code drafts stay local until Visual mode is selected. The syntax highlighter creates fixed React spans with text children, without an HTML rendering sink. Visual conversion continues to sanitize before `setContent`, and sanitizes the normalized callback HTML. A genuine host `value` replacement while Code mode is open discards the stale draft; unchanged prop rerenders preserve it. A parent reassigning the exact same string is not an observable replacement. The Laravel server sanitizer and authorization remain mandatory; the editor exposes no read-only prop, and this phase does not introduce one. The existing Format action is not a semantic-preserving HTML formatter for all arbitrary markup; avoid using it for whitespace-sensitive content without review.

Run the existing validators, build, both isolated React consumer lanes, and both Laravel suites. The browser contract requires 113 groups per React lane (105 previous plus 8 new). The synthetic source fixture includes scripts, encoded unsafe links, event handlers, SVG and srcdoc; verify raw text is inert, committed output is sanitized, and approved rich blocks round trip. No real external video traffic is required; the existing synthetic iframe route is used. Review the exact patch before installing. If baseline mismatches, stop and supply the changed local source.

Manual check: type source without switching modes, confirm host still sees the last committed value; switch to Visual to commit; verify save/reopen and backend sanitation in a disposable consumer. Do not test using live customer data. Host application save controls must clearly require source commit before saving; server sanitization is never optional.
